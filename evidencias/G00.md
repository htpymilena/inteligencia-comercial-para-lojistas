## Execução local

Ferramentas observadas: Docker 29.5.3, Compose v5.1.4 e Node 24.17.0 no host;
Python 3.12 na imagem backend. O host não possui Python 3.12/.venv, por isso
os checks Python foram executados em contêiner. `backend/requirements.lock` e
`frontend/package-lock.json` fixam as dependências; as quatro imagens base
estão fixadas por digest em `compose.yaml` e nos Dockerfiles.

- `docker compose config --quiet` passou com variáveis sintéticas e falhou com
  variável obrigatória ausente, sem imprimir o valor de qualquer segredo.
- `docker compose -p nexo_apply_m00 --env-file .env.apply.local up --build -d`
  construiu os dois Dockerfiles e iniciou `db`, `backend` e `frontend`.
- `docker compose ... ps` mostrou banco e backend saudáveis; HTTP publicado em
  `127.0.0.1:8000` e `127.0.0.1:5173`, sem porta de banco publicada.
- `GET http://127.0.0.1:8000/health` e
  `GET http://127.0.0.1:5173/health` retornaram
  `{"status":"ok","service":"nexo-api"}`.
- Um marcador em `m00_persistence_probe` tinha contagem 1 antes e depois de
  `docker compose ... up --force-recreate -d`, com o mesmo volume nomeado.
- Ao encerrar, `docker compose ... down` removeu os contêineres e a rede, mas
  `docker volume inspect nexo_apply_m00_nexo_pgdata` confirmou que o volume
  isolado permanece. O arquivo `.env.apply.local` segue ignorado pelo Git para
  permitir revisão local sem expor seus valores no relatório.
- `npm run smoke:status` abriu `/status` no Chrome headless, confirmou resposta
  real de `/health`, falha induzida e recuperação sem mock ativo. Captura:
  [g00-status.png](g00-status.png).
- O frontend passou em `npm run lint`, `npm run build` e 76 testes Vitest.
  O bundle final não continha nomes de segredos do backend nem os valores
  sintéticos usados neste projeto isolado.
- Com os testes montados somente para leitura no contêiner backend,
  `pytest tests/unit tests/contract -q` aprovou 58 testes; `ruff check` passou.
  `pytest tests/integration -q` aprovou 12 testes contra PostgreSQL 16 em
  schemas exclusivos, sem skips. `mypy` passou em 42 arquivos e `pip check`
  não encontrou dependências quebradas.
- Após fixar os digests e atualizar o frontend, `docker compose ... up --build -d`
  voltou a construir e iniciar os três serviços. Os dois caminhos HTTP de
  `/health` continuaram respondendo 200; Playwright repetiu a verificação
  sucesso → falha → recuperação e atualizou a captura.
- `openspec validate m00-ambiente-e-contrato --strict`, `git diff --check` e
  leitura sintática do YAML de CI passaram. Os últimos 200 registros de log
  backend foram conferidos sem encontrar os valores sintéticos de senha/JWT.
